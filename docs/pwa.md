# FarmFlow PWA

FarmFlow is a mobile-first Progressive Web App.

## Current PWA surface

| Asset | Location | Purpose |
| --- | --- | --- |
| Manifest | `/manifest.webmanifest` | App name, icons, colors, display mode, shortcuts |
| Service worker | `/sw.js` | Precache, offline fallback, runtime caching, push |
| Offline page | `/offline.html` | Shown when a navigation fails offline |
| Icons | `/icons/*.png` | 192/512/maskable PNGs (generated by `npm run icons`) |
| Favicon | `/favicon.svg` | Browser favicon |

## Caching strategy

Low-bandwidth by design (farm sites often run on 2G/3G or metered data):

- **Navigation** → network-first; fall back to cache, then the cached app
  shell (any route reloads offline), then `/offline.html`.
- **`/assets/*` build files** → cache-only. Vite content-hashes names, so the
  same file is never re-requested; repeat visits download zero bytes.
- **Other same-origin GET** (icons, `/uploads/*` images, …) → network-first
  with cache fallback, so seen files also render offline.
- **`/api/*`** → stale-while-revalidate with a 45s TTL. A cached response is
  served instantly; within the TTL there is **no network call at all**, after
  it the cache is returned while a background refresh keeps it current. This
  makes the 60s badge polling and repeated list views nearly free. Offline,
  the latest cached copy is served; with no cache a `503 OFFLINE` envelope is
  returned. A background refresh that fails with 401/403 (expired token)
  evicts the entry so the next request re-authenticates instead of serving
  an eternally stale copy.
- The API also gzips responses (`compression`, level 6), cutting typical list
  payloads by ~80%.
- Precached at install: `/`, `/offline.html`, `/manifest.webmanifest`, icons.
- The app never loads external fonts, CDNs, or third-party scripts.

## Push notifications

- Web Push (VAPID) is implemented end-to-end. The client subscribes through
  the browser Push API and stores the subscription on the backend
  (`/api/push/subscribe`); delivery is driven by the same pipeline as in-app
  notifications and respects the user's notification preferences.
- VAPID keys live in `.env` (`VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY`).
  Delivery is fire-and-forget — dead subscriptions (404/410) are pruned
  automatically, and failures never block task operations.
- The Settings → Notifications *Push* toggle subscribes/unsubscribes this
  browser device. Permission status and browser-support warnings are shown
  inline.
- `push` event renders a notification from the payload (`title`, `body`,
  `url`); notifications are tagged per task so duplicates collapse, and they
  are skipped when an app window is already focused (the in-app badge covers
  it).
- `notificationclick` focuses an existing window (navigating to the task) or
  opens the target URL.

## Offline data & sync (Phase 11) — implemented

Offline reads and writes work without any special IndexedDB read-cache: the
service worker's `/api/*` stale-while-revalidate cache already serves the
latest known server state after a reload, and React Query keeps it in memory
during a session. Phase 11 adds the offline **write** path:

- **Local mutation queue** — an IndexedDB store (`farmflow` DB, `sync_queue`
  store) records task status changes (`start`/`complete`), updates
  (progress/deadline/priority via PATCH), and comments that fail with a
  network error. The queue survives reloads and is removed only after the
  server acknowledges a replay.
- **Background sync** — queue drain (replay in creation order) runs 1.2s after
  startup, on the `online` event, when the tab becomes visible with pending
  work, and every 60s while work is pending (no polling when idle). This is a
  portable client-side loop rather than the Service Worker `sync` event, which
  iOS Safari doesn't support.
- **Optimistic UI** — a queued mutation patches the task detail and list
  caches immediately (status, progress, comment placeholder) and shows an
  "saved offline" toast; the OfflineBanner reports the pending/syncing count.
- **Conflict resolution** — server-authoritative last-write-wins for
  status/progress/deadline. Comments are append-only, and replay is exactly
  once (a queue item is deleted when the server acknowledges it), so no
  duplicates. A 4xx replay (e.g. task already finished) is treated as
  acknowledged; network failures and 5xx keep the item for the next attempt.
- On a successful flush, task queries are invalidated so the server state
  replaces optimistic values.
- **Offline session** — the auth store (status/user/token) is persisted to
  `localStorage` (`farmflow-auth`), and a refresh that fails with a network
  error/timeout/5xx keeps the session instead of clearing it. A reload
  therefore stays signed in offline (logging in requires the server).
- **Offline reads** — React Query runs with `networkMode: 'always'`, so
  queries still execute while offline and are answered by the service
  worker's API cache instead of sitting paused on a spinner. On reconnect
  all queries are invalidated.

Not queued (fail with a normal error): attachments (binary, sizeable) and
task deletion.

## Testing checklist

- Install prompt appears (Android/Chrome/Edge; iOS add-to-home-screen).
- Manifest parses and icons render.
- App loads offline after first visit.
- Start/complete/progress/comments made offline show optimistic changes, an
  offline banner, and upload on reconnect without duplicates.
- Push notifications display and deep-link correctly.
